# v1.3 implementation status — not release-ready

Do not update Cargo version, tag, push or publish a v1.3 release until every release criterion below has a tested implementation. This file is an implementation checkpoint, not user documentation. The full agreed target is in [the graph/UML design](gne-class-object-v2-design.md). The existing language reference continues to describe only working behavior.

## Implemented and tested in the current working tree

- `//` source comments replace `#` across `.laml`, `.lamlstyle`, examples, tests and relevant docs; `https://` in unquoted text is preserved. `#` is no longer consumed as a comment.
- `style-classes=` replaces `classes=` in graph and sequence parsing, examples, tests and docs.
- GNE named relation and sequence message `@id` syntax are accepted; old `name:` syntax still works as a temporary compatibility path until graph and sequence migration is complete.
- LSS universal `*` selector is available at the lowest precedence. GNE `shape: rectangle|ellipse|diamond|note` is measured, routed to its visible contour and exported consistently; UML types reject shape overrides that alter their notation. Nonrectangular compartments still need a designed inset geometry and currently fail explicitly.
- Graph `type: class|object` parsing, basic class/interface/enum/datatype/object nodes, compact `<T>` template headings (binding checks pending), explicitly named anonymous objects, source-ordered body rows and dividers, class attribute/operation compartment checks, object slots, basic folded one-line notes with dotted node/member attachment; globally explicit member-to-member edge attachments; undirected `--` plus the first checked UML operators (`-->`, `..>`, `--|>`, `..|>`, `*--`, `o--` and combinations); object diagrams reject class-only operators; basic UML multiplicities and roles at association ends are parsed, validated and collision-checked; selectable SVG body text, object underlining, enum/interface/datatype headings, PNG/PDF export from the same SVG, and undirected soft adjacency are present. See `tests/class_object_v13.rs` and the working drafts in `docs/drafts/`.
- Preexisting sequence and graph tests remain passing. Strict Clippy and rustfmt pass; actual release validation must be rerun after all changes.

## Validated additions since the preceding checkpoint

- Notes now accept `note Hinweis { ... }` with multiple literal text lines, blank lines and `\\}` for a literal closing brace. Their text is measured as one multiline note; there are no graph compartments inside a note block.
- A first conservative UML relationship check rejects note-to-class associations, inappropriate member endpoints, association-end adornments on dependency/generalization/realization, self-generalization. `..|>` is not restricted to interface realization: UML also defines generic Realization. This is not a full UML conformance audit.
- Optional classifier visibility glyphs (`+ - # ~`) render without changing the node ID; nodes and relations with `<<stereotype>>` suffixes render visibly without becoming styling classes. Reserved `<<bind>>` rejects until binding checks are implemented. `layout { relation[orders].source : multiplicity=above; role=below }` now gives collision-checked mandatory end-label sides, with analogous `.target` rules.
- LSS `display: none` works for graph nodes, relations and members; visible references and mandatory layout rules to hidden elements fail. Filtering is consistent between layout and routing.
- The current local graph changes passed the full test suite, rustfmt and strict Clippy. Full release validation and documentation remain outstanding.

- Notes can attach to named graph relations with `Hinweis .. relation[orders]`; routing creates a deliberate T-junction rather than a false bridge, with collision and reference checks. Generic nodes can use the same edge anchor, while UML-specific non-note attachments remain rejected until their notation is audited.
- GNE and class nodes now admit named boundary ports with scoped or explicit IDs, measured visible names, default left/right attachment, mandatory `port[id] : side=left|right|top|bottom`, and LSS port coloring/hiding. Visible references and mandatory rules targeting hidden ports fail. Top/bottom ports reserve measured label bands; nonrectangular contours and advanced UML port rules remain explicitly unsupported.

## Open before v1.3 can be claimed complete

- Finish the agreed ID model across all declaration kinds and sequence references, including unambiguous scoped container paths and consistently global explicit `@id`. Graph members and named ports already support scoped defaults and diagram-wide explicit IDs.
- Implement node containers/qualified references, nonrectangular port geometry and relation-end side port layout, generalized edge-to-edge anchors and UML association-class attachment, n-ary association junctions, qualifiers, association classes, complete UML association-end semantics (visibility, qualifiers and explicit end-label placement), precise marker clearance/routing, stereotypes and full UML-specific validation for the now visible generalization, realization, dependency, navigability and whole/part diamonds. Do not mistake an implemented glyph for complete UML validation.
- Finish UML classifier-specific shapes/ports, mandatory side and end-label layout rules, remaining visibility/abstract/static details with consistently embedded font faces, compartment hiding and icon styling, conditional Phosphor attribution in SVG/PNG/PDF metadata. Basic member, member[kind=...], member[ID], member.style-class and contextual LSS selectors now affect measured color/font-size and explicit member hiding; hidden anchored members fail rather than leaving dangling edges. Default member IDs can be targeted as `Node::member`, with ambiguous overloads rejected; explicitly aliased members have no hidden default alias.
- Implement local template binding validation and audited UML `<<bind>>` notation, package/enum/datatype special rules, lollipop eligibility, complete object-link validation and UML restrictions. Audit normative ambiguities (including mixed class/instance diagrams) before claiming standard compliance.
- Change all *published* v1.3 examples to built/tested sources, add generated preview images and README references, update `docs/language-reference.md`, language contract, and user guides to exactly the shipped implementation. Add positive/negative end-to-end tests for all agreed constructs and check all four CI targets.
- Only after complete local validation: bump version to `1.3.0`, commit, push from an authenticated shell when explicitly confirmed, verify four-platform CI, then tag/release and confirm assets. No remote publication has been attempted.
