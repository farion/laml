# v1.3 implementation status — not release-ready

Do not update Cargo version, tag, push or publish a v1.3 release until every release criterion below has a tested implementation. This file is an implementation checkpoint, not user documentation. The full agreed target is in [the graph/UML design](gne-class-object-v2-design.md). The existing language reference continues to describe only working behavior.

## Implemented and tested in the current working tree

- `//` source comments replace `#` across `.laml`, `.lamlstyle`, examples, tests and relevant docs; `https://` in unquoted text is preserved. `#` is no longer consumed as a comment.
- `style-classes=` replaces `classes=` in graph and sequence parsing, examples, tests and docs.
- GNE named relation and sequence message `@id` syntax are accepted; old `name:` syntax still works as a temporary compatibility path until graph and sequence migration is complete.
- LSS universal `*` selector is available at the lowest precedence. GNE `shape: rectangle|ellipse|diamond|note` is measured, routed to its visible contour and exported consistently; UML types reject shape overrides that alter their notation. Nonrectangular compartments still need a designed inset geometry and currently fail explicitly.
- Graph `type: class|object` parsing, basic class/interface/enum/datatype/object nodes, compact `<T>` template headings (binding checks pending), explicitly named anonymous objects, source-ordered body rows and dividers, class attribute/operation compartment checks, object slots, folded multiline notes with dotted node/member attachment; globally explicit member-to-member edge attachments; undirected `--` plus the first checked UML operators (`-->`, `..>`, `--|>`, `..|>`, `*--`, `o--` and combinations); object diagrams reject class-only operators; basic UML multiplicities and roles at association ends are parsed, validated and collision-checked; selectable SVG body text, object underlining, enum/interface/datatype headings, PNG/PDF export from the same SVG, and undirected soft adjacency are present. See `tests/class_object_v13.rs` and the working drafts in `docs/drafts/`.
- Preexisting sequence and graph tests remain passing. Strict Clippy and rustfmt pass; actual release validation must be rerun after all changes.

## Validated additions since the preceding checkpoint

- Notes now accept `note Hinweis { ... }` with multiple literal text lines, blank lines and `\\}` for a literal closing brace. Their text is measured as one multiline note; there are no graph compartments inside a note block.
- A conservative UML relationship check rejects note-to-class associations, inappropriate member endpoints, association-end adornments on dependency/generalization/realization, self-generalization, package endpoints without validated notation, and aggregation/composition whose whole is not a class. `..|>` is not restricted to interface realization: UML also defines generic Realization. This is not a full UML conformance audit.
- Optional classifier visibility glyphs (`+ - # ~`) render without changing the node ID; abstract classifiers also display a measured `{abstract}` fallback so the annotation survives exporters without an italic face. Nodes and relations with `<<stereotype>>` suffixes render visibly without becoming styling classes. Bare `<<bind>>` rejects; the checked `<<bind(T->String)>>` substitution requires a local target template and the correct dashed arrow. See `uml-template-bindings-v13.md` for the OMG notation limit. `layout { relation[orders].source : multiplicity=above; role=below }` now gives collision-checked mandatory end-label sides, with analogous `.target` rules.
- LSS `display: none` works for graph nodes, relations and members; visible references and mandatory layout rules to hidden elements fail. Filtering is consistent between layout and routing.
- The current local graph changes passed the full test suite, rustfmt and strict Clippy. Full release validation and documentation remain outstanding.

- An allowlisted set of vendored Phosphor icons supports `icon: "folder"` on generic nodes and `symbol-rendering: icons; icon-set: phosphor` for visible classifier/member visibility markers. The upstream MIT notice is embedded only in exports that actually draw an icon: SVG metadata (including outlined SVG), PNG iTXt, PDF Info.Subject. The bundled upstream notice and pinned icon provenance are in `assets/phosphor/`; legal review of the exact export-notice policy remains outstanding.
- Binary association ends accept `qualifier(id:UUID,region:String)`; measured qualifier rectangles attach between classifier and relation line. They are collision-checked and exported in SVG/PNG/PDF; dependencies and object links reject them. OMG UML 2.5.1 §11.5.4 was checked for box position; qualifier-owned property semantics are not modeled.
- The UML navigability/dependency arrow uses an open stick head rather than a misleading filled triangle. Solid generalizations across unsupported differing classifier kinds or through a cycle fail, and an association class cannot show a different name on its association path.
- A 24×24 diamond represents a n-ary association with at least three distinct classifier arms; `association Verordnet` places its name beside the small diamond in a measured, collision-checked node envelope. Typed UML association classes with member compartments attach by a dashed T-junction to exactly one plain named binary association; unlinked or mismatched notation fails.
- Nested package frames group class and GNE nodes with qualified default paths (e.g. `Vertrieb.Lager.Produkt`), scoped styling, measured child containment, fixed-size failure, and routing across their own borders. Cross-scope mandatory separations project conservatively to package boundaries; alignment offsets now project through nested packages without moving child nodes outside their frames. Folder tabs and visible relation labels are rendered without covering package content.
- Notes can attach to named graph relations with `Hinweis .. relation[orders]`; routing creates a deliberate T-junction rather than a false bridge, with collision and reference checks. Generic nodes can use the same edge anchor, while other UML non-note attachments remain rejected until their notation is audited.
- GNE and class nodes now admit named boundary ports with scoped or explicit IDs, measured visible names, default left/right attachment, mandatory `port[id] : side=left|right|top|bottom`, and LSS port coloring/hiding. Visible references and mandatory rules targeting hidden ports fail. Top/bottom ports reserve measured label bands; nonrectangular contours and advanced UML port rules remain explicitly unsupported.

## Open before v1.3 can be claimed complete

- Finish ID scoping and overload resolution across all declaration kinds. Sequence participants, named messages, notes, continuations and fragment IDs now share one validated namespace; execution IDs remain lifeline-scoped. Graph packages, members and named ports support qualified scoped defaults and diagram-wide explicit IDs.
- Finish exact container obstacle/label clearance, nonrectangular port geometry, relation-end side port layout, advanced qualifier anchoring, complete UML association-end semantics, precise marker clearance/routing, and full UML validation of generalization, realization, dependency, navigability and whole/part diamonds. Do not mistake an implemented glyph for complete UML validation.
- Finish UML classifier-specific shapes/ports, mandatory side and end-label layout rules, remaining visibility/abstract/static details with consistently embedded font faces, compartment hiding, and a legal review of the export notice policy. Basic GNE node icons, UML/GNE visibility glyph replacements and conditional Phosphor metadata are implemented and tested for SVG/PNG/PDF. Basic member, member[kind=...], member[ID], member.style-class and contextual LSS selectors now affect measured color/font-size and explicit member hiding; hidden anchored members fail rather than leaving dangling edges. Default member IDs can be targeted as `Node::member`, with ambiguous overloads rejected; explicitly aliased members have no hidden default alias.
- Complete UML template classifier notation (inline `<T>` is a documented LAML simplification), package/enum/datatype special rules, lollipop eligibility, complete object-link validation and UML restrictions. Audit normative ambiguities (including mixed class/instance diagrams) before claiming standard compliance.
- Six buildable examples and generated previews now cover classes, objects, n-ary associations, nested packages, template bindings and optional generic icons; existing generic README previews were regenerated after the open-arrow change. README, language reference, language contract and the class/object guide describe the implemented subset; the all-target local suite and preview consistency check pass. Finish documentation review against all agreed semantics, add positive/negative end-to-end tests for remaining constructs, and check all four CI targets.
- Only after complete local validation: bump version to `1.3.0`, commit, push from an authenticated shell when explicitly confirmed, verify four-platform CI, then tag/release and confirm assets. No remote publication has been attempted.
