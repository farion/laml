# v1.3 implementation status — scoped release candidate

v1.3 is an image language with an audited UML-notation subset, not a UML abstract-syntax model. Unsupported notation fails instead of being presented as valid UML. The [graph/UML design](gne-class-object-v2-design.md) and [UML notation audit](uml-class-object-conformance.md) define that boundary. Do not tag or publish until all four platform jobs pass on the versioned commit. The language reference describes delivered behavior only.

## Implemented and tested in the current working tree

- `//` source comments replace `#` across `.laml`, `.lamlstyle`, examples, tests and relevant docs; `https://` in unquoted text is preserved. `#` is no longer consumed as a comment.
- `style-classes=` replaces `classes=` in graph and sequence parsing, examples, tests and docs.
- GNE named relation and sequence message `@id` syntax are accepted; old `name:` syntax still works as a temporary compatibility path until graph and sequence migration is complete.
- LSS universal `*` selector is available at the lowest precedence. GNE `shape: rectangle|ellipse|diamond|note` is measured, routed to its visible contour and exported consistently; UML types reject shape overrides that alter their notation. Nonrectangular compartments still need a designed inset geometry and currently fail explicitly.
- Graph `type: class|object` parsing, basic class/interface/enum/datatype/object nodes, UML dashed-corner template parameter boxes (GNE retains compact inline `<T>` headings), explicitly named anonymous objects, source-ordered body rows and dividers, class attribute/operation compartment checks, object slots with unique feature names, folded multiline notes with dotted node/member attachment; globally explicit member-to-member edge attachments; undirected `--` plus the first checked UML operators (`-->`, `..>`, `--|>`, `..|>`, `*--`, `o--` and combinations); object diagrams reject class-only operators; basic UML multiplicities and roles at association ends are parsed, validated and collision-checked; selectable SVG body text, object underlining, enum/interface/datatype headings, PNG/PDF export from the same SVG, and undirected soft adjacency are present. See `tests/class_object_v13.rs` and the working drafts in `docs/drafts/`.
- Preexisting sequence and graph tests remain passing. The pre-release local run passed 251 tests, strict Clippy, rustfmt, POSIX installer checks and the release build; repeat validation on the final versioned commit.

## Validated additions since the preceding checkpoint

- Notes now accept `note Hinweis { ... }` with multiple literal text lines, blank lines and `\\}` for a literal closing brace. Their text is measured as one multiline note; there are no graph compartments inside a note block.
- UML body checks now reject arbitrary text or `static`/`abstract` object slots, modified or duplicate enumeration literals, non-public interface features, abstract attributes and malformed forced field/method notation. Member front modifiers can occur in any order; duplicates and conflicting kinds fail. Object links can show end names (UML 2.5.1 §9.8.4) but still reject end multiplicities and qualifier boxes. A conservative UML relationship check rejects note-to-class associations, inappropriate member endpoints, association-end adornments on dependency/generalization/realization, self-generalization, package endpoints without validated notation, and aggregation/composition whose whole is not a class. `..|>` is not restricted to interface realization: UML also defines generic Realization. This is not a full UML conformance audit.
- Optional classifier visibility glyphs (`+ - # ~`) render without changing the node ID; abstract classifiers also display a measured `{abstract}` fallback. Matched Inter Regular/Italic fonts are now bundled, italic widths measured, and the italic face embedded only in SVGs that use it; PNG, outlined SVG and vector PDF use the same faces. Nodes and relations with `<<stereotype>>` suffixes render visibly without becoming styling classes. Bare `<<bind>>` rejects; the checked `<<bind(T->String)>>` substitution requires a local target template and the correct dashed arrow. See `uml-template-bindings-v13.md` for the OMG notation limit. `layout { relation[orders].source : multiplicity=above; role=below }` now gives collision-checked mandatory end-label sides, with analogous `.target` rules.
- LSS `display: none` works for graph nodes, relations and members; visible references and mandatory layout rules to hidden elements fail. Filtering is consistent between layout and routing.
- The local graph changes passed the full test suite, rustfmt and strict Clippy. Publication still depends on four-platform CI of the final commit.

- An allowlisted set of vendored Phosphor icons supports `icon: "folder"` on generic nodes and `symbol-rendering: icons; icon-set: phosphor` for visible classifier/member visibility markers. The upstream MIT notice is embedded only in exports that actually draw an icon: SVG metadata (including outlined SVG), PNG iTXt, PDF Info.Subject. The bundled upstream notice and pinned icon provenance are in `assets/phosphor/`; Frieder confirmed on 2026-10-30 that his professional lawyer had thoroughly reviewed the metadata-only Phosphor notice policy. This records the user's confirmation, not an independent legal opinion.
- Binary association ends accept `qualifier(id:UUID,region:String)`; measured qualifier rectangles attach between classifier and relation line. They are collision-checked and exported in SVG/PNG/PDF; horizontal and vertical exits are supported, and diagonal or own-classifier-overlapping placement fails. Dependencies and object links reject them. OMG UML 2.5.1 §11.5.4 was checked for box position; qualifier-owned property semantics are not modeled.
- The UML navigability/dependency arrow uses an open stick head rather than a misleading filled triangle. Solid generalizations across unsupported differing classifier kinds or through a cycle fail, and an association class cannot show a different name on its association path.
- A 24×24 diamond represents a n-ary association with at least three distinct classifier arms; `association Verordnet` places its name beside the small diamond in a measured, collision-checked node envelope. Typed UML association classes with member compartments attach by a dashed T-junction to exactly one plain named binary association, or by a dashed line to a named n-ary association diamond. Names shown on both symbols must match, and one association cannot own two association classes; unlinked or mismatched notation fails.
- Nested package frames group class and GNE nodes with qualified default paths (e.g. `Vertrieb.Lager.Produkt`), scoped styling, measured child containment, fixed-size failure, and routing across their own borders. Cross-scope mandatory separations project conservatively to package boundaries; alignment offsets now project through nested packages without moving child nodes outside their frames. Folder tabs and visible relation labels are rendered without covering package content.
- Notes can attach to named graph relations with `Hinweis .. relation[orders]`; routing creates a deliberate T-junction rather than a false bridge, with collision and reference checks. UML note links to nodes reject unvalidated relation labels and stereotypes rather than implying named UML relationships. Generic nodes can use the same edge anchor, while other UML non-note attachments remain rejected until their notation is audited.
- GNE and class nodes now admit named boundary ports with scoped or explicit IDs, measured visible names, default left/right attachment, mandatory `port[id] : side=left|right|top|bottom`, and LSS port coloring/hiding. Named direct node-to-node relations can additionally mandate `relation[id].source|target : side=left|right|top|bottom` independently of label-side rules; named ports accept matching relation-side mandates, member rows accept left/right, conflicting constraints on shared ports fail, and all source/target side pairs on named self-loops have bounded exterior routes. Visible references and mandatory rules targeting hidden ports fail. Top/bottom ports reserve measured label bands. Generic folded-note top ports stay clear of the cut corner, and automatic routes now intersect the actual folded outline instead of its rectangular bounding box; generic ellipse/diamond ports attach to the contour with measured in-shape label clearance. Advanced UML port rules remain explicitly unsupported.

## v1.3 acceptance boundary

- The supported graph/UML notation is the image-generating subset in `docs/class-object-diagrams.md` and `docs/uml-class-object-conformance.md`. Local parser, geometry, SVG/PNG/PDF and rejection tests pass. Scoped/default identity, graph ports, member anchors, end-label side mandates, qualified names, packages, n-ary associations, association classes, checked bindings, compact interfaces and visible/hideable members have positive and negative coverage. Unsupported UML syntax and semantically misleading overrides fail explicitly.
- Routing is bounded and deterministic: nodes, container tabs, visible contours, markers, labels, qualifiers, existing routes and bridge humps are checked. If no safe candidate exists, the build fails rather than drawing an unsafe route. This does not promise a route for every topologically feasible graph or complete UML semantic validation.
- Abstract syntax/type checking, profile loading, operation execution, external classifier resolution, advanced parameter/property syntax, full UML port semantics, optional UML compartments and other excluded constructs in the notation audit are *not* v1.3 features. They must not be described as supported. GNE nonrectangular compartments deliberately fail until an inset geometry is designed.
- Seven documented examples and their previews pass source consistency checks and build as SVG, PNG and PDF. The Phosphor notice policy was confirmed as lawyer-reviewed by Frieder; attribution remains conditional on an icon actually rendered.

## Remaining release gates

1. On the final versioned commit, rerun `cargo fmt --all --check`, `cargo test --locked --all-targets`, `cargo clippy --locked --all-targets -- -D warnings`, installer checks, and the release binary/examples. Every Rust source file must remain at most 500 lines.
2. Push the versioned main commit, verify Linux x86-64, macOS Intel, macOS ARM and Windows x86-64 CI. The older run on `ed0a61b` failed on Windows because its documentation test assumed LF line endings; `tests/documentation.rs` now normalizes CRLF and has a regression test. A Linux cross-target metadata check cannot substitute for Windows tests.
3. Only after four green CI jobs: push annotated `v1.3.0`, verify all four release archives and `SHA256SUMS`. Do not claim publication until the tag-triggered release succeeds.
